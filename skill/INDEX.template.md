# [项目名称] · 记录索引（INDEX）

> 版本 v1.0.1

> **类型标记**：`[接力]` 链条节点（有下一步）——接手沿此读，当前相关工作上下文 / `[完成]` 已完成——接手不读，审视/归档才读 / `[废弃]` 废弃需求——不读，留痕防未来误做（**废弃由管理者决定，AI 不自行废弃——只留痕不执行**）。
> **可信度标注**：来自会话汇总的历史（存量项目接入）标「会话汇总」，正式工作记录标「正式」。
> **只存项目工作记录**：技能自身事务（复盘/版本/恢复登记）不登本文件，归 REVIEWS.md（元管理分流）。
> **双写机制**：主文件只留最近 N 行（N 由 MAP 配置，默认 20）；每次收工**同时写主文件 + 归档文件**（archives\INDEX_archived.md，唯一全量索引）；主文件超 N 行时旧行**移入**归档文件（归档文件永不删）——**行永不丢失，不做物理删除**。行数标注与调整话术见 SKILL.md 第六节。
> **日常读取**：接手 AI 默认只读主文件 N 行；不够或查全部历史 → 归档文件（唯一全量索引）。

> 编号规则：`XXNNNN`（两位字母=分类 + 四位数字=顺延序号）——分支字母首次使用先在 MAP「分支编号登记」注册，避免撞号；同分支内数字按**数值**严格递增（EX10000 > EX9999）；**编号=记录/版本序号（每次收工递增），任务卡的稳定身份是文件名，卡上编号字段仅指当前版本**。冲突裁决：同分支内数值大覆盖小；跨分支不比较编号、不以时间戳裁决——双方在自己 reports 留双方记录，交管理者裁决，时间戳仅作辅证（跨平台时钟不可信）；**撞号重试**：写后验发现同分支同编号已存在 → 后写者编号 +1 重写本行并在自己 reports 留痕。
> **reports 文件归档**：reports 篇数达到 MAP「reports 归档阈值」（默认 20）即归档最旧篇到 archives\——归档的 reports 文件不参与活跃链编号，INDEX 对应行的"交接文件"列更新指向 archives\。
> 极端情况：单分支数字超 9999 → 按数值自然递增到五位（EX9999 → EX10000），比较始终按数值、不按字符串；若需换新周期，归档后同分支从 0001 重新开始并在 MAP 登记新周期。
> 交接列：同工作区内写相对路径 `reports\xxx.md`；历史 / 跨工作区记录写完整路径（如 `F:\...\旧工作区\reports\xxx.md`）。
