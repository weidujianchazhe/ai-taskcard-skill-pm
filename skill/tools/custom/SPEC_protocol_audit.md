# 协议审计脚本规格（SPEC_protocol_audit）

> **用途**：生成「协议审计」类本地脚本（检查为主、默认只读）。AI 落地时把每个检查点映射为平台命令（见 SCRIPT_SPEC 平台适配表）。
> **触发**：收工后自动跑 / 管理者手动跑 / 定期检查（tools\checks 开关）。
> **生成粒度**：每检查点 = 一个独立脚本（check_<检查点>_<主题>.ps1，默认一功能一脚本）；整集/分组运转由运转器编排（见 SCRIPT_SPEC「生成粒度与运转框架」）。

---

## 检查点 1：收工门禁（四件套真伪）

**目的**：抓「收工核对（4/4）」打勾走过场。
**输入**：最近一份交接 reports（或用户指定）。
**逻辑**：
```
读 reports → 校验 6+1 块标题齐全（本次需求/本次涉及工程信息/改动点/验证结果/数据影响/下一步/任务卡更新）
解析「任务卡更新」块 → 目标卡（更新 或 移卡到 archives\done\）
卡✓：目标卡存在；且若本次锚点非「—」→ 卡上「已提炼」非「—」且不早于锚点（文件名/时间比较）
INDEX✓：INDEX.md 含本次编号行；编号 = 已登记分支 + 数值递增（见检查点 4）
STATE✓：STATE.md 有本次写入证据（mtime/hash 变化，或「最近更新」≥ 交接时间）
移卡型：卡已在 archives\done\ 且 INDEX 有 [完成] 行
```
**输出**：每件 [通过]/[问题]；问题附「缺哪件 + 建议动作」。
**边界**：交接内容真假 → [待核]（脚本只验「件是否齐、字段是否填」，不验「做没做对」）。
**注意**：「交接✓ 自身存在」天然通过（旧版跳过）——本规格改为校验 6+1 块标题齐全，堵住「只有个空文件也打勾」。

---

## 检查点 2：越界改动（蠢动作）

**目的**：抓改了任务卡「涉及」以外文件。
**输入**：活跃任务卡 + 代码根路径（卡上「代码根路径」字段或 MAP）。
**逻辑**：
```
解析「涉及」字段 → 允许文件/目录列表
git 可用：git status/diff 取实际改动 → 差集（实际 - 允许）= 越界
无 git：用 mtime 窗口近似（时间窗内变动的文件），结果标注「近似」
```
**输出**：越界文件列表 [问题]。
**边界**：无 git 的近似结果 → 标注「近似」；允许目录内的文件 → 不算越界。

---

## 检查点 3：并发冲突（两个 AI 同写一文件）

**目的**：写前读/写后验的执行情况 + STATE 体量封顶。
**输入**：STATE.md / 目标任务卡 + MAP 规则段「STATE 字数上限」+ 写动作发生时刻。
**逻辑**（供落地时挂钩收工脚本）：
```
覆盖写前：记录 mtime + 内容哈希
写入后：重读 mtime/hash → 与写前不一致 → 有人插写（冲突）
体量：STATE.md 字数 > MAP「STATE 字数上限」（默认 15k）→ 体量超限
```
**输出**：[通过] 或 [问题]（冲突嫌疑 + 建议按冲突裁决规则处理；体量超限 + 建议把历史段移入 reports\，只留当前快照）。
**边界**：需在 AI 声明写入后立即执行才有意义；纯事后审计只能看 hash 变化 → [待核]。时间戳仅作辅证——跨分支冲突不以时间戳裁决（跨平台时钟不可信），双方 reports 留痕交管理者；辅证启发式：编号递增 + 时间戳不倒退为正常，倒序则时间戳可疑（提请人工留意，不作裁决依据）。

---

## 检查点 4：编号与 INDEX 完整性

**目的**：编号体系合规（格式验证对抗偷懒的核心资产）。
**输入**：INDEX.md 全文（含归档断点）、MAP 分支编号登记。
**逻辑**：
```
编号格式：两位字母 + 4~5 位数字
同分支：数字严格递增（按数值比较，EX10000 > EX9999，不按字符串）
分支字母：必须在 MAP「分支编号登记」中存在（未登记 = [问题]）
类型标记：∈ {[接力], [完成], [废弃]}
[接力] 链：主文件截断处 → 下一跳在 archives\INDEX_archived.md 可续（不判断链为违规，指向归档即可）
交接列：指向的文件存在（reports\ 或 archives\）
```
**输出**：违规行列表 [问题]；归属/价值不确定 → [待核]。
**边界**：编号是否对应「真实干过的活」→ [待核]（格式只能证序列合规）。

---

## 检查点 5：命名与引用完整性

**目的**：reports 命名规范 + 锚点不悬空。
**逻辑**：
```
reports\*.md 文件名匹配 日期_主题_AI标识 规范（按 MAP 命名规范；AI 标识含「-」）
tasks\ 活跃卡「上次交接」锚点 → 指向存在（reports\ 或 archives\）
模板文件未被当成工作文件改动
```
**输出**：[问题] 列表。
**边界**：主题用词是否贴切 → [待核]。

---

## 检查点 6：版本漂移（三处同步 + 源包）

**目的**：SKILL/README/MAP 版本行不一致 = 改了没同步。
**逻辑**：
```
读 SKILL.md frontmatter version、README.md / MAP.template.md「版本 vX」行（BLUEPRINT 不参与版本同步——只记设计要点，无版本行不报警）
源包路径（MAP 环境段「技能源包路径」）存在时：对比工作区 vs 源包
任一不一致 → [问题]：哪份旧 / 缺哪个版本字段
```
**输出**：[问题] 清单 + 「按 SKILL.md 维护规范同步 3 处并递增版本」建议。
**边界**：内容漂移但版本号恰好一致 → [待核]（建议模型复核）。

---

## 检查点 7：路径注册表对账（MAP vs 实际文件系统）

**目的**：抓「地图过时」——注册表登记的路径已被移动/改名/删除，MAP 静默失效，沿图找文件的 AI 全部迷路且无报警。
**输入**：MAP 路径注册表全部行 + 环境段「技能源包路径」「工作区备份方式」。
**逻辑**：
```
逐行取注册表路径 → 校验存在性（目录/文件）
不存在 → [问题]：列出失效行 + 建议「更新 MAP 注册表该行」（更新为写操作，需用户确认）
跳过规则（不算问题）：① 模板占位行（如 `[新路径]`）——跳过；② 标注「首次归档时创建 / 首次 X 时创建」的延后创建行（如 archives\INDEX_archived.md）——不存在时降为 [待核] 提示（「尚未创建，属正常」），不报 [问题]
「技能源包」行：按环境段「技能源包路径」校验（填「—」未登记 → 跳过，不算问题）
reports\ / archives\ 内文件完整性 → 归检查点 4（交接列存在性）与恢复点 5（对账），此处只验目录本身存在
```
**输出**：失效路径清单 [问题]。
**边界**：路径存在但内容为空/损坏 → [待核]（脚本只验存在性，不验内容）；整目录误删属恢复问题 → 转恢复点 1~3 + 按 MAP「备份方式」兜底。
