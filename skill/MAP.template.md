## 三、协议（协同协议 · 派生快照，权威源为工作区 SKILL.md）

> 以下 8 行为高频速记，覆盖一次常规收工的全部动作；细则（缺失补全 / 并发裁决 / 档案红线全文）见工作区 SKILL.md 第三节。

1. **任务卡驱动**：接手先读对应任务卡（tasks\），开工前在卡「承接」认领，不漫读全项目
2. **收工分流**：未完成 → 必须建卡；有下一步 → 完整交接 + 覆盖式更新任务卡；无下一步 → 简化总结 + 移卡到 archives\done\（不删卡）
3. **收工四件套**：交接 reports → 卡更新/移卡 → INDEX 加一行（类型 [接力]/[完成]/[废弃]，行永不丢失——主文件超 N 行移入归档文件）→ STATE 条目级写（禁止整文件盲覆盖）
4. **最小交接**：6 块 + 第 7 块「任务卡更新」（有对应任务卡时必填）；不写 diff、不复制代码
5. **命名规范**：reports `YYYY-MM-DD_主题_AI标识.md`（AI 标识：`{平台}-{AI名}-{短码}`，短码 2~4 位随机；写前先 list 目录确认无同名）；任务卡按工作命名
6. **编号与并发**：编号 XXNNNN——分支字母先在 MAP「分支编号登记」注册、同分支数字按数值严格递增、撞号 +1 重写并留痕；写前读 + 写后验；跨分支冲突不比编号、不以时间戳裁决——留痕交管理者，时间戳仅辅证
7. **提炼回卡 + 进度锚点**：读 reports 后增量提炼回卡（每篇最多被读一次）；工作中落点即覆盖写卡「进度锚点」行，中断沿锚点 + git status 续作，收工沉淀后清「—」
8. **档案与元管理**：reports\ 与 archives\ 禁删禁移（唯一例外=收工归档，移后同步 INDEX 行指向）；新增文件/路径/分支登记 MAP；技能自身事务写 REVIEWS.md，不写 reports\、不登 INDEX
