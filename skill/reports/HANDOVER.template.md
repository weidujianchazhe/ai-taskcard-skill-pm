# 交接记录规范（每条记录一个文件）

> 版本 v1.0.1

> 文件名：`YYYY-MM-DD_主题_AI标识.md`（AI 标识：`{平台}-{AI名}-{短码}`，短码 2~4 位随机——同平台多实例不撞名；写前先 list reports\ 目录确认无同名）。
> 完成代码修改、产出交付、用户新决策、遇到未解决问题时，必须新建一条记录。
> **最小化原则**：只写本任务需要的信息——不写完整 diff、不复制代码、不贴无关历史、不重复 MAP 已有内容。
> **元管理分流**：技能自身事务（REVIEWS 复盘、版本漂移、恢复动作登记）**不写本文件**——追加写工作区 REVIEWS.md；本目录只存项目工作记录。
> 所有未完成工作均走完整收工四件套（交接 reports → 卡 → INDEX → STATE）；完成型走简化四件套（简化交接 reports → 移卡到 archives\done\ → INDEX → STATE），无"不落盘"例外。

## 交接模板（6 块必填 + 第 7 块「任务卡更新」有对应任务卡时必填）

### 交接  YYYY-MM-DD HH:MM

- **本次需求**：一句话（用户要什么）
- **本次涉及工程信息**：只列本任务相关的文件路径（不给全部目录树）
- **改动点**：文件 + 位置 + 改了什么（3~5 条，每条一行；工程有 git 时每条附 commit hash——精确追溯锚点，需要完整 diff 时 git show 即得）
- **验证结果**：是否验证、检查了哪些功能
- **数据影响**：数据目录变化 / 是否需要迁移
- **下一步**：下一位 AI 从哪里继续 + 待用户确认的决策点
- **任务卡更新（第 7 块）**：本次提炼的要点/锚点 → 覆盖更新对应任务卡（有对应任务卡时必填）→ **并同步 STATE**（收工四件套：交接 → 卡更新/移卡 → INDEX → STATE；STATE 按条目级写——并行收工时只更新自己任务条目与人读区）

> **收工核对（4/4）**：交接 ✓ / 卡更新或移卡 ✓ / INDEX ✓ / STATE ✓
> **卡质量自检**：要点可执行（做什么+在哪）/ 涉及具体路径 / 上次交接指向 reports（无交接才填「—」）
