# 设计蓝图（BLUEPRINT）

> 版本 v1.2.1

> 本文件即设计蓝图的权威速记（下方要点覆盖核心机制，包内有效）。HTML 版 `项目管理轻量化工作分配蓝图.html` 为包外补充设计文档——本技能包纯 MD、不携带 HTML；发布方将其置于包外可见位置（如仓库/发布根）即可，缺失不影响运行。

## 设计要点（速记）

1. **跨阻碍**：多 AI / 跨平台 / 跨时间 / 跨项目——AI 接手以更小读取代价理解工作
2. **按需读取**：项目可复杂沉重，接手只读任务相关部分（任务卡一张 ± 1 次 reports）
3. **创建是通用第一步**：任何项目先创建管理目录，创建后不再重复读技能
4. **存量接入**：轻量登记 + 渐进整理，不做深度历史整理（LEGACY_ONBOARDING.md）
5. **人读区 + AI 区**：人读区（3 行摘要）+ AI 区（工作坐标）；人读区由 AI 区自动生成，覆盖更新时同步重写
6. **技能体量原则**：只加现有机制覆盖不了的；协议登记不打包实现
7. **稳定标识（v1.2.0）**：`TASK-ID` / `EVENT-ID` / `DESIGN-ID` 创建后永不变更；文件名可改，引用只用 ID
8. **设计生命周期（v1.2.0）**：设计卡（DESIGN-ID + 状态机 + 生命周期门禁）——**未批准的设计不得生成执行卡**，批准/拒绝/废弃均写 EVENT-ID
9. **三种模式（v1.2.0）**：`light` / `standard` / `coordination`——各自的文件集、角色与检查、升级路径；升级即扩集，历史不回写
10. **单写者与一致性（v1.2.0）**：权限矩阵 + 单写者责任；CAS / 原子写 / 冲突文件 `CONFLICT_*.md`；写前读 revision/hash、写后验；跨分支冲突不以时间戳裁决
11. **两处封顶装置（v1.2.1）**：`INDEX 主文件行数` 与 `STATE 字数上限`——都是接手 AI 阅读成本的**封顶装置，不是可扩容量**；超限按覆盖式纪律把历史段移入 reports\\ 与归档文件，分层读取结构不得合并
12. **边界声明（v1.2.0）**：本包只定义协议、模板与脚本**生成规范**；不实现或默认启用运行时守护进程、自动归档器、权限系统或持续监督
