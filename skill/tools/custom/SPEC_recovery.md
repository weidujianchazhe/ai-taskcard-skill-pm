# 自愈辅助脚本规格（SPEC_recovery）

> **用途**：生成「恢复辅助」类本地脚本。默认只读 + 输出「草稿/建议」；任何写操作（落盘重建文件等）必须经用户确认后执行。
> **触发**：数据文件丢失 / STATE 损坏 / 锚点断链 / 版本过时 / 需要查历史时，AI 读本文件生成或直接执行其逻辑。

---

## 恢复点 1：任务卡重建脚手架

**目的**：任务卡丢失时，把「机械可做的事」交给脚本，留下语义部分给 AI。
**输入**：INDEX.md、reports\、archives\。
**逻辑**：
```
INDEX 近期行 → 找最近 [接力] 行 → 取其「交接文件」列 → 沿链列候选 reports（按日期倒序）
生成「重建任务卡草稿」：标题/编号建议（分支登记 + 递增）/ 上次交接（锚点组候选）/ 涉及（从 reports 抽路径）自动填
描述/要点/最后折叠 → 留空 + 标注 ⚠待AI填（需读候选 reports 补全语义）
```
**输出**：草稿到终端（或按用户确认写入 tasks\）。
**边界**：重建内容来自 reports 的推断 → 草稿的语义字段必须标「待确认」，禁止直接落成正式卡。

---

## 恢复点 2：STATE 恢复辅助

**目的**：STATE 损坏时从最新 reports 恢复骨架。
**逻辑**：
```
读最新含「下一步」的 reports（按 [接力] 锚点或时间倒序）
抽取：当前进展 / 进行中任务 / 决策点 → 生成 STATE 草稿（人读区 3 行 + AI 区骨架）
```
**输出**：草稿（待 AI/用户确认后覆盖写入 STATE.md）。
**边界**：reports 不全 → 草稿标注缺口「待按需整理」，不编造。

---

## 恢复点 3：锚点断链修复

**目的**：卡上「上次交接」指向不存在（被归档/误删）时给出修复建议。
**逻辑**：
```
扫所有活跃卡 → 解析「上次交接」每个锚点 → 目标存在？
不存在 → 在 INDEX（主 + 归档）按主题/时间找实际位置（可能移入 archives\）→ 输出「建议把锚点改为 X」
```
**输出**：断链清单 + 建议新锚点（[待核]：AI 确认后再改卡）。
**边界**：找不到对应文件 → 建议标「数据待补」，不伪造锚点。

---

## 恢复点 4：版本过时检测（资产层 vs 工作区）

**目的**：资产层版本 > 工作区 → 提示拉取更新（对应「缺失补全：缺失或过时」）。
**输入**：MAP 路径注册表「技能资产层」路径（未登记 → 提示先登记）。
**逻辑**：
```
对比各协议文件（SKILL/README/MAP）在工作区 vs 资产层的版本行
资产层更高 → [问题]：列出过时文件 + 「从资产层复制模板实例化重填」步骤
```
**输出**：过时清单 + 更新步骤（写操作需用户确认）。
**边界**：无资产层路径 → 输出提示「先登记技能资产层路径」，不算违规。

---

## 恢复点 5：归档一致性

**目的**：reports 超阈值、完成卡对账、INDEX 主文件截断断点。
**逻辑**：
```
reports\ 计数 > MAP 配置（默认 20）→ 列出最旧 N 篇建议移 archives\（按月）
tasks\ 无卡但 archives\done\ 有卡：核对 INDEX 有无 [完成] 行对应
INDEX 主文件达到 N 行 → 提示「可更改」+ 断点位置指向 archives\INDEX_archived.md
```
**输出**：建议清单（移动/登记为写操作，需用户确认）。
**边界**：是否归档是维护决策 → 脚本只列候选，不自动移。

---

> **通用边界**：本规格所有「写」动作（落盘草稿、移动文件、更新锚点）默认输出建议，必须用户确认；「语义填充」（描述/要点/总结）一律归 [待核]，由当前 AI 读源文件后完成。
