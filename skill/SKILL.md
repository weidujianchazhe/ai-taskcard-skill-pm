# 项目管理轻量化工作分配（技能入口）

> **定位**：通用型项目管理技能，不为特定项目服务。核心哲学——项目可以复杂沉重，AI 接手只读所需：负担不随项目规模增长。
> **本质目标（跨阻碍）**：跨越平台、AI、时间、项目等阻碍，让接手 AI 以更小读取代价理解工作需求、降低出错率。
> **存量项目（已开工无管理结构）**：先读 `LEGACY_ONBOARDING.md`（轻量登记 + 渐进整理，不深度整理历史）。

---

## 一、触发时机

1. **新项目开工前**：初始化协同工作区（创建管理目录 + 填写初始信息）
2. **长期未动项目接手前**：按需读取工作文件（任务卡驱动，不重复读本技能）
3. **存量项目接入**（已开工、无管理结构）：读 `LEGACY_ONBOARDING.md` 执行接入

## 二、使用流程

```
① 确认工作区根 {WORKSPACE_ROOT}（用户选择一次：默认或自定义；管理目录子文件夹技能自动创建）
② 创建管理目录（通用第一步，任何项目都要）：
   MAP.md / STATE.md / tasks\ / reports\ / INDEX.md / archives\ / tools\
③ 填写初始信息：MAP 占位符替换（环境/规则/协议/路径注册表）
④ 登记首条任务卡（tasks\，按工作命名）
⑤ 运行（此后不再重复读技能，只按工作文件运行）：
   读任务卡 → 干活 → 收工分流（覆盖式更新/移卡）→ INDEX 登记
   （tasks\ 为空时按用户指令新建卡；无卡 = 当前无活）
   （多卡时：用户指定任务 → 去 tasks\ 找同名/相近名卡；多卡同名时问用户确认）
```

## 三、核心协议（速查）

| 协议 | 内容 |
|---|---|
| 任务卡驱动接手 | 读对应任务卡（描述/要点/涉及/锚点）→ 够用直接开工；不够沿锚点读 reports |
| 收工分流 | **未完成 → 必须建卡**（无论是否即时复制型）；有下一步 → 完整交接 + 覆盖式更新任务卡；无下一步 → 简化总结 + **移卡到 archives\done\**（不删卡，保留完成记录）；**收工四件套：交接 → 卡更新/移卡 → INDEX → STATE，落盘后逐项核对** |
| 下一步判断标准 | 有下一步 = 用户还要继续 / 活没做完 / 有遗留问题；无下一步 = 用户明确说"做完了" / 活全清 |
| 覆盖式更新 | 任务卡/STATE 永远覆盖为最新，不追加、不滚雪球；历史归 reports + INDEX |
| 沉淀再前进 | 读 reports 后提炼增量覆盖回卡 → 每篇最多被读一次 |
| INDEX 类型标记 | `[接力]` 沿链读 / `[完成]` 审视读 / `[废弃]` 留痕防误做 |
| 双阅读层 | 人读区（3 行摘要）+ AI 区（工作坐标）；人读区为 AI 区派生视图（任务←描述首句、状态←状态字段、下一步←要点①），覆盖更新时机械重写 |
| 最小交接 | 6 块 + 第 7 块「任务卡更新」（落盘接取型必填） |
| 命名规范 | reports `YYYY-MM-DD_主题_AI标识.md`（写前先 list 目录确认无同名）；任务卡按工作命名 |
| 内容级并发安全 | 写前读（覆盖写 STATE/任务卡、追加写 INDEX 前先读最新）· 写后验（写后读回确认落盘）· STATE 独占（当前负责 AI 更新，并行 AI 只写自己的卡与 reports）· 冲突裁决（不同字段合并、同字段仅在同分支内按编号数字大覆盖小；跨分支以时间戳后写为准并在 reports 留双方记录；编号递增 + 时间戳不倒退为正常，倒序则时间戳可疑） |
| 缺失补全 | 技能资产层为权威源：项目工作区技能文件缺失或过时（资产层版本更高）→ 从资产层复制模板实例化重填；数据文件（任务卡/reports）丢失从 INDEX/reports 恢复，INDEX 也丢了 → 标「数据待补」，不伪造；**任务卡丢失** → 从 INDEX 近期行找最近 [接力] 行 → 沿交接文件列读最新 reports → 从 reports 重建任务卡（描述/要点/涉及/锚点）→ 在 tasks\ 新建；**STATE 损坏** → 从最新 reports 恢复（最新交接记录里有当前进展/下一步）；任何恢复动作顺手记一行 REVIEWS 阻碍点（事件自动采集） |

> 术语：即时复制型 = 尚未落盘为独立卡、仅存在于当前对话中的工作；落盘接取型 = 已落盘为独立任务卡、由下一位 AI 从卡接取的工作。

## 四、初始化检查清单

- [ ] 工作区根 {WORKSPACE_ROOT} 已向用户确认（默认或自定义）
- [ ] 管理目录已创建：MAP / STATE / tasks\ / reports\ / INDEX.md / archives\ / tools\
- [ ] MAP 占位符已全部替换为项目真实信息
- [ ] 首条任务卡已建（含人读定位区 + AI 字段区）
- [ ] 交接模板第 7 块「任务卡更新」就绪
- [ ] INDEX.md 已初始化（表头 + 类型标记说明）
- [ ] 存量项目：已按 LEGACY_ONBOARDING.md 完成轻量登记（如适用）

## 五、管理自检（定期/按需）

- [ ] 接手成本是否恒定 ≈ 任务卡一张 ± 1 次 reports？（膨胀点：任务卡/STATE 是否覆盖式）
- [ ] 任务卡是否只留活跃？完成即移卡到 archives\done\、废弃留痕？
- [ ] INDEX 类型标记是否正确？[接力] 链是否连续？
- [ ] 收工分流是否执行（有下一步更新卡 / 无下一步移卡到 archives\done\）？
- [ ] 人读区与 AI 区是否同步更新（无单边分叉）？
- [ ] 技能本身问题是否已记入 REVIEWS 复盘（元管理回路闭环：阻碍→根因→建议→处置→沉淀进技能）？

> 完整设计蓝图见 `BLUEPRINT.md`（其 6 条要点即权威速记）；HTML 版 `项目管理轻量化工作分配蓝图.html` 为包外补充设计文档（本包纯 MD 不携带，发布方置于包外即可）。

## 六、维护规范（技能自身迭代）

- **改协议必同步 3 处**：修改任何核心协议时，同步 `SKILL.md` 核心协议表 / `README.md` 核心规则 / `MAP.template.md` 协议段，并递增版本号，防版本不同步
- **改进先复盘**：技能改进先记入 REVIEWS（阻碍→根因→建议→处置→沉淀进技能），再落地修改
- **落地后同步三副本**：模板源 / 安装副本（.user_skills）/ 发布包（skill\ 副本 + ZIP）；同步时递增版本号，资产层版本高于项目工作区版本时提示拉取更新
