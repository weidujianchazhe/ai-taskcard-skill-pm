# 可选工具区（tools\）

> **按需拉动，不进接手路径**：AI 接手工作时无需读取本目录；只有具体需求（检查/图示/定时/报告）时才读对应工具规范。

## 内置工具

| 工具 | 用途 | 触发 |
|---|---|---|
| `checks\` | 项目检查（人工触发为主，AI 定期排查开关默认关闭） | 项目管理者有需求时 |
| `visualize\` | 可视化规范（平台无关） | 需图示/图表表达结构关系时 |
| `schedule\` | 定时任务（提醒/周期检查/定期汇报） | 需要定时能力时 |
| `report\` | 报告生成（日报/周报取数） | 需要报告时 |
| `custom\` | 本地脚本生成指南（用户自定义脚本） | 某平台 AI 操作反复出问题时 |

## 防失控规则（三铁律）

1. **按需拉动**：只有需要时才读对应工具规范，不提前加载
2. **不进接手路径**：工具规范不加入接手必读流程
3. **只放规范不放平台实现**：协议登记，实现靠各平台原生能力（不打包实现）

## 调用方式（管理者可直接调用）

- 工具可**直接调用**：管理者在任意会话（新会话 / 工作已暂停或终止的会话）直接说「调用 X 工具 / 生成周报 / 检查记录 / 跑本地脚本」，AI 读对应规范或执行已生成脚本，无需先浏览目录。
- 已生成的自定义脚本（项目工作区根目录，如 check_local.ps1 / check_local.sh）与内置工具规范，同属可直接调用的工具。
- 上下文独立：调用工具只读工作区文件，不打断其他正在工作的会话。
- 与「查看项目」的区别：查看项目是「浏览目录 → 发现工具 → 才决定」；调用工具是「已知要哪个工具 → 直接调用」。

## 新增工具（如需扩展）

- 按上述三铁律在 `tools\` 下新增子目录 + 规范文件，并在本 README 登记
- 不新增"平台原生就能做到"的工具（如搜索/翻译/写作/纪要转写/问答——产出按现有协议自然沉淀即可）
- 若某平台纪律问题反复出现，可针对该平台补本地检查脚本（单平台实现、不进技能包）；技能侧只做协议登记
